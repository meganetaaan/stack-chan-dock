# 保存した録音を読み上げの声に使う

Pocket日本語の既存female03に加え、このアプリで保存した本人の録音から話者状態を作り、明示的に選べます。録音も派生した声のデータも端末内だけで処理します。録音の外部送信、クラウド推論、話者学習はありません。他の4エンジンの声は変更しません。

## 手順

1. 同じアプリID・署名のversionCode 6のAPKで上書き更新します。既存のPocket合成モデルZIPは再取得不要です。
2. 声の設定でPocketを選び、既存モデルを準備します。
3. 「自分の声を録音」を開きます。「声を作る追加モデルを取り込む」で `pocket-tts-ja-reference-encoder-v1.zip` を一度取り込みます。
4. 保存済み録音の「この録音から声を作る」を押します。**先頭から最大5秒**を使います。録音全体はそのまま保存されます。静かな場所で録音し、先頭の長い無音を避け、試聴で確認してください。
5. 作成完了後、「この声を使う」を押します。作成だけでは使用中の声を変えません。設定を閉じ、通常の読み上げ・会話で確認できます。
6. 「標準の声（female03）を使う」で元に戻せます。選択は再起動やエンジンを切り替えた後にも復元します。

Pocket未準備、録音中、試聴中、未保存の録音がある間は変換・切り替えできません。変換中は録音・試聴・会話・モデル変更を禁止します。「処理を中止」、画面離脱、バックグラウンド移行で中止し、自動再開しません。画面を閉じる際は古い処理の終了を待ってから会話を許可します。処理の失敗やキャンセルは前の選択を保持します。切り替えが既に確定していた場合は、その確定済みの選択を復元します。

## モデルとライセンス

追加ZIPは18,012,371 bytes、SHA-256 `3d09fd90ee09a538980fd9164470a3108dab3fbef7e57ddb3e9b0f4496a6e860` です。APKにモデル重みは埋め込みません。既存の合成モデルZIPは変更しません。追加ZIPはAPKに固定したマニフェスト、サイズ、SHA-256に一致するファイルだけを受け入れ、検証失敗・キャンセル時は以前の追加モデルを保護します。
APKを選ぶとエラーになる場合の案内は [追加モデルZIPの取り込み](ENCODER_IMPORT_HELP.md) を参照してください。versionCode 7以降は選ぶZIP名を画面に明示します。
両モデルの検証マニフェストはGitの改行変換対象外とし、既存ZIPに対応する改行バイトも含めて保存します。再checkout後もAPKとZIPの完全一致検証を保ちます。

- `mimi_encoder.onnx`: 39,261,982 bytes、SHA-256 `5a6927d66a3585ad220f446ef8d4429948a17f10257661304cf42d61653865f6`
- `bos-before-voice.f32`: 4,096 bytes、SHA-256 `ec11dd25e9e0c647bd11a5708d1d8de723a93dcfc44198b0b642467380e4af9c`
- 日本語チェックポイント: `ce597c6d2efa5bac163079d6318591de9dbad67a`、元の重みSHA-256 `848b60fcfbcd3f8468e0c5419b2e1cb331673df59502f3cc430509a3a3294cb7`
- 既存PC exportのstock Pocket TTS 3.3.0用FP32 wrapperを再利用。exporter pin `e801e7d6c2692121a39e80ae525cb5265174a495`。追加学習・量子化はありません。

派生エンコーダとBOSは、既存の日本語モデルと同じCC BY-NC 4.0（表示・非営利）です。コードはPocket TTS / PocketTTS.cpp exporterのMITです。既存のPocket利用条件確認とクレジットを継続します。本人の同意のある声で利用してください。この機能を作るために別の重みを取得したり、新しい認証・規約承諾を行ったりする必要はありません。個人の録音そのものを公開・再許諾する処理はありません。

## 推論と保存

PCM16を既存のresamplerで24kHzモノラルへ揃え、先頭最大120,000サンプルをFloatへ変換します。エンコーダの出力に日本語固有のBOSを付け、既存の `flow_lm_main.onnx` の空の状態へprefillして18個のKV状態を作ります。新しいSDKやAndroid PyTorchは不要で、既存の分離されたONNX Runtime CPU1を使います。

エンコーダは変換の時だけ読み込み、成功・失敗・中止の全経路で閉じます。FlowLMのprefill前にエンコーダを解放します。空きRAMは既存のPocketと同じ1.5GiB以上かつOSがlowMemoryでないことを確認します。モデルを閉じてもアロケータやOSが即座にメモリを返す保証はありません。余裕が足りない場合は他のアプリを閉じて再試行してください。

話者状態は `files/pocket-voices/<UUID>/` に保存します。最大5秒では64フレームのKVキャッシュ約3.15MBです。メタデータに元録音ID・PCM hash、使ったサンプル数、合成モデル・エンコーダ・BOSのfingerprint、キャッシュhashを記録します。破損・別モデルの状態は読み込まず、破損した選択の起動復元ではfemale03へ戻します。通常の音声切り替えでは候補のテンソルを全て用意してから選択ポインタを原子的に保存し、メモリ上の声を交換します。準備・保存に失敗した候補は解放し、前の声を残します。

話者状態の削除・共有・書き出しUIはありません。バックアップ除外は既存設定を継続し、アプリデータ消去・アンインストールでは録音と話者状態も消えます。
保存録音だけは、名前を確認して [削除](RECORDING_DELETION.md) できます。元録音を削除しても作成済みの話者状態と選択は維持し、その声を引き続き使えます。

## 検証範囲

人工PCMのPC CPU1検証で、既存日本語チェックポイントのPython処理とKotlinのエンコード/prefillを比較します。明示的な声の切り替えでPCMが変化すること、同じ声の再現、female03へ戻した際の元PCMとのバイト一致、保存失敗時の選択保持、ネイティブRunOptionsの中止後の再変換、既存の合成・停止・USB PC mockを検証します。

エンコーダ単独のPCプロセスの参考値は、5秒入力が約0.65秒・237MiBピーク、10秒が約1.60秒・641MiBピークです。このためAndroidの初版は最大5秒に限定しています。これはAndroidの速度・PSSや実音声の品質を示す測定ではありません。

**未検証**: Android上の新規ONNXのロード・オペレータ対応、実機RAMピーク、LLM/STT同居時の速度・メモリ、本人の録音を用いた声の類似度・読み精度、実画面・権限/着信/背景移行のOS動作、実Dock USB。UIはソースとComposeのコンパイルで確認します。NucBoxのGPU/Vulkan、マイク、COMは使っていません。
